# Specification

Every ID has a test tagged `# SPEC: <ID>`.

| ID | Statement |
|---|---|
| FBC-01 | A free-programming-books list line `* [title](url) - authors (formats) (licence)` becomes one source with its title, URL, authors, formats, stated licences, archived flag, the heading path above it and the list's language; lines that are not entries (index links, headings, prose, a link without its `(url)` or closing `)`) become nothing. The list's language is the part of the file name after its last `-` when that part is 2 or 3 lower-case letters, optionally followed by `_REGION` (`pt_BR`); otherwise (no `-`, `langs`, `cp`, a longer part) it is `en`. Headings are 1 to 6 `#` and a space; the authors follow a `-` or `–` separator and end at the first group; groups may nest, and a `)` outside any group is ignored. |
| FBC-02 | A source's ID is FNV-1a 64 over the normalized URL (lower-case scheme and host, no fragment, no trailing slashes); normalization is idempotent; a string with no scheme or no host is only trimmed; sources with one ID merge into one, keeping every listing and every format and licence, archived when either is, and taking URL spelling, title, authors and language from the mention whose first listing comes first (ties broken by those fields), and merging is order-independent. |
| FBC-03 | Each Hillside catalog page yields its web links (id and title) and the start of the next page (the first page is fetched without `?start=`, page n at `?start=n`); a web link or `start=` whose number has no digits is skipped, and one of more than 18 digits is skipped rather than shortened; each Hillside book category yields its book pages, the links under `/patterns/books/<category>/` that have text, each URL once with the text of its first such link, in page order; a web link whose redirect is known is catalogued under its target URL. |
| FBC-04 | Only hillside web links and GitHub-hosted free-programming-books meta-lists are followed to depth 2; their links become depth-2 listings that name the list they came from, at most 2000 per list; every other meta-list is recorded in meta.json with the reason it was not followed. |
| FBC-05 | Every source has exactly one relevance under the consumer's rules: core when a heading of one of its listings or its title matches a keyword (short keywords only as whole words), hillside depth-1 entries core when the rules say so, listings in out-of-scope files out, otherwise adjacent; a hand decision in overrides.json wins. |
| FBC-06 | Building twice from the same inputs gives byte-identical meta.json, sources.jsonl and triage.json, whatever the order the inputs were read in; every line of sources.jsonl is valid UTF-8 JSON (a byte that does not start a valid UTF-8 sequence becomes U+FFFD); within a source, listings are ordered by depth, origin, file, heading path and via, and formats and licences are sorted. |
| FBC-07 | No module under src/ imports a networking module; only tools/catalog_fetch.nim does. |
| FBC-08 | A source the consumer names in its config ("listed") is a depth-1 source of origin `listed` and is core, and states the licences the config gives it (none when it gives none). |
| FBC-09 | The consumer's config.json is read in full (user agent, cache location and its environment override, pinned commit, hillside switch, free-programming-books switch `fpb`, commercial-only switch `commercialOnly`, triage rules, listed sources with their licences); a missing required field is an error that names it. With `fpb` off, nothing is fetched from or read out of free-programming-books, and the pinned commit is not checked. |
| FBC-10 | With `commercialOnly` on, catalog_build writes nothing and exits 1 when a source states no licence or a licence not in `commercialLicenses`, naming each such source and licence; `licenceErrors` returns one line per such source and licence, and none when every source may be used commercially. |
| FBC-11 | In a fetched page, a link is an HTML `<a ...>text</a>` whose `href` attribute (any case, a whole attribute name, quoted with `"` or `'` or unquoted) is not empty, or a Markdown `[text](url)` whose brackets do not cross a line and whose URL is not empty (a title after the URL is dropped); links are returned in page order; a relative href is resolved against the page's base and kept as written when the base is empty; HTML entities in the href are decoded, and the text has its tags removed, its entities decoded and its whitespace collapsed (Markdown text is only trimmed). |
